# Version 1.0 Readiness Audit and Successor Plan

**Status:** Audit complete; successor plan is a proposal awaiting Patrick Mee's product decision.
**Owner:** Patrick Mee.
**Audit date:** 2026-10-18.
**Source:** `main` at `0e9f4f5caf6d11aae6e086c77032c17a6ffc8dbf`; released gameplay is the immutable [`v0.7.1`](https://github.com/PatrickMee/emerald-isle/releases/tag/v0.7.1) package.
**Review trigger:** Patrick's product and in-game judgment, a changed RimWorld build, or a 1.0 release candidate

## Verdict: REVISE

The released set can credibly become Version 1.0 through integration, clarity, verification, and release hardening. No demonstrated missing gameplay capability calls for another headline system. The colony has an accessible material root (oats, stone, flax, a household hearth), independent animal and preservation choices, and several explicit paths into mature vanilla play. Electricity makes some early tools situational; it does not erase every Emerald Isle choice. Patrick's ongoing real-colony play validates the unchanged released mechanics as a combined experience; the remaining product direction is not a release approval.

Complete the bounded **1.0 Cohesion Fix Set** before release hardening:

1. **Player guidance:** make the oat milling-to-food route, flax-to-linen route, and the hearth's later preservation/brewing roles discoverable through concise existing descriptions or a short player guide. Name the actual workbench and research boundary where needed; do not add a tutorial system or alter production balance. The local readiness test build at `1f00b0d` updates these descriptions and the install, upgrade, and removal guidance; confirm the changed words are visible and clear in game before finalizing them.
2. **1.0 presentation and release operations:** prepare a version-accurate About/Workshop description and preview, inspect at gameplay and Workshop thumbnail size, check attribution and visible English text, and rehearse the existing exact-artifact release/rollback procedure. Human release approval remains required.

Patrick Mee decided on 2026-10-18 to defer translation-file completeness until after 1.0. Missing English DefInjected entries alone are not part of this fix set or a 1.0 release gate. A genuinely missing, broken, or unintelligible *visible English* string remains a defect to address if candidate review demonstrates it. This deferral is recorded explicitly rather than presented as translation completeness.

The two work items are Routine copy, art/metadata, and release-process work unless a concrete compatibility or cultural risk escalates them. They do not authorize new gameplay. The `.gitignore` Python-cache fix in this audit removes one verified release-builder impediment; it does not change the published package.

Tunic and cloak can later be replaced by specialized apparel without invalidating the textile route. |

The installed 1.6 assembly's `ThingDef.AllRecipes` combines a bench's direct recipes with recipes listing that bench as a user. The present hearth registers its exclusive bills directly once; regression validation rejects duplicate exposure. Recipe availability uses normal research gating. The installed food-policy generator operates on ingestible definitions and preferability, and the food-selection path applies `optimalityOffsetHumanlikes`; source XML has the released reserve offsets on flatbread and smoked meat. Apparel has normal `defaultOutfitTags`. These are structural explanations, not substitutes for observing policies and bill menus in game.

**UI pressure:** the hearth declares 18 bills with all supported DLC, including vanilla cooking, burning, and baby-food bills, plus nine Emerald Isle food/drink entries. Electric/fueled stoves each gain six Emerald Isle bills; the machining table gains four linen alternatives beside vanilla cloth bills. Do not reorder or remove public bills solely from this count. At the v0.7.1 audit baseline, the hand-quern description did not say where its output was cooked, and the flax descriptions did not name processing work locations. The local `1f00b0d` test build addresses that copy gap; its visible presentation remains to be checked. Existing `About.xml` and the Workshop draft inventory the content but are not contextual in-game guidance.

## Findings by disposition

**Release blockers:** None demonstrates a missing product capability. A 1.0 release is blocked procedurally until the two Cohesion Fix Set items, changed-text and presentation review, exact candidate checks, and maintainer release approval pass. Patrick's real playthrough supplies human evidence for the unchanged mechanics; they do not need broad replay for this copy-only change. New failures in the remaining checks can become concrete blockers. Missing translation-file entries alone are not a blocker under Patrick's 2026-10-18 deferral.

**Bounded fixes and polish:** the two Cohesion Fix Set items above. Also correct the local Python-cache ignore rule (included with this audit): before it, importing `release_lib` made a new `tools/__pycache__/release_lib.cpython-314.pyc` untracked and the release builder rejected the otherwise clean checkout. The no-bytecode workaround produced the published digest; ignoring caches makes the ordinary builder reproducible again. A Python 3.14 `ElementTree` deprecation warning in `validate-runtime-contracts.py` is non-blocking tool maintenance.

**Optional after 1.0:** complete the deferred English DefInjected entries for `EI_MillOatsBulk` label, description, and job string; audit the Kerry cattle `meatLabel` and both animal definitions' attack-tool labels and `labelNoLocation` values using verified RimWorld 1.6 injection paths. Preserve public keys and DefNames, then check missing/orphan keys and long strings. More advanced cultural expression may be proposed only with its own player decision and milestone approval. More food-bill automation, broad mod compatibility, additional translations, or expanded world/myth content are candidates, not 1.0 exit criteria. Rebalance only if controlled play finds a dominant choice or dead end. Separately, `GOVERNANCE.md` recommends backup maintainer access before 1.0 as a succession safeguard; Patrick should consider it, but its absence is not an automatic release blocker.

**Rejected / outside this plan:** the rejected [Ringfort Foundations](ringfort-foundations-discovery.md), its prototype gate and conditional tower, as well as festivals, peat, factions, mythology, world generation, and a substitute marquee system. The old [delivery plan](version-1.0-delivery-plan.md) is historical after the Gate A rejection; this proposal does not silently approve an alternative feature.
